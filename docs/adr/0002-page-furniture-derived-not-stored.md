# Page furniture is derived from page text on read, never stored or cut from it

Running headers, footers and watermarks are left out of a Highlight's quote and overlay, but canonical page text keeps them and anchors still index into it. We rejected stripping furniture at import because it would change canonical page text, shifting the offsets of every stored anchor and breaking the browser/server agreement on what an offset means. Instead the shared Page Text module detects furniture as line ranges with a pure, deterministic heuristic over all of a Document's page texts, and the server applies it when deriving the quote and returns the remaining body segments on each Highlight. We rejected storing furniture ranges (a migration plus backfill) because detection is cheap and page text is immutable per Document, so recomputing is always consistent; the cost is that tuning the heuristic later changes segments of existing Highlights while their stored quotes stay as created.
